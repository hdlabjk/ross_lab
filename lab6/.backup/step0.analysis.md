# Step0 タイミング解析 (synth_1 合成後)

- 対象: `mreduc` (7a100t-fgg676, -2)
- クロック: `sys_clk` 3.000 ns (333.3 MHz)
- レポート: [timing0.rpt](timing0.rpt)

## サマリ

| 項目 | 値 |
|---|---|
| WNS (セットアップ) | -1.494 ns |
| TNS | -9045.681 ns |
| セットアップ違反エンドポイント | 6680 / 20709 |
| WHS (ホールド) | +0.136 ns (違反なし) |
| パルス幅 | 違反なし (WPWS 1.000 ns) |

結論: タイミング制約を満たしていない (セットアップ違反あり)。

## 違反エンドポイントの内訳

| エンドポイント | 本数 | 最悪スラック (ns) |
|---|---|---|
| DSP48E1:A | 3840 | -1.494 |
| DSP48E1:B | 2304 | -1.342 |
| FDCE:D | 152 | -0.499 |
| FDCE:CE | 192 | -0.479 |
| FDPE:CE | 192 | -0.479 |

## 問題点

### 1. DSP48E1 入力側 (違反の大半)

- 最悪パス: `channel[0].u_dsp/delay_line_reg[15][*]/C` → `channel[0].u_dsp/p_0_out/A[*]`
- データパス遅延 1.044 ns (FF の clk-to-Q と配線のみ、ロジック段数 0)。
- DSP48E1 のセットアップ時間が 3.269 ns で、周期 3.0 ns より長い。
- 全 128 個の DSP48E1 が `AREG=0, BREG=0, MREG=0, PREG=1` で、入力レジスタ (A/B) と乗算結果レジスタ (M) を使っていない。
- 乗算が組み合わせで DSP 内部を通る形になり、333 MHz では経路の長さにかかわらず成立しない。
- 原因箇所: `src/dsp_pipeline.sv` の `products[i] <= delay_line[i] * coeffs[i];`
  (乗算結果を直接 FF に入れており、A/B/M レジスタが推論されない)。

### 2. 統計エンジン側 FDCE/FDPE (軽微)

- D ピン (152 本, 最悪 -0.499 ns):
  `xbar_out_reg[0][1]/C` → `stats[0].u_stats/mean_reg_reg[23]/D`、ロジック 10 段、データ遅延 3.391 ns。
  `stats_engine.sv` の平均計算が 1 サイクルで組み合わせ実行されている。
- CE ピン (384 本, 最悪 -0.479 ns):
  `ce` / `data_valid` が約 11000 個の FF に fanout している影響が疑われる (経路の詳細は未確認)。

## 対策案

- DSP 入力側: 乗算の前後にパイプラインレジスタを追加し、A/B/M レジスタを使わせる。
  - A/B レジスタを使うとセットアップ要件が大きく下がる。
  - M レジスタまで使うとさらに緩和される。
- 統計エンジン: 演算を複数段に分割する。
- `ce` の fanout: `ce` を複製する、または `max_fanout` を指定する。

RTL/XDC を変更する場合は `update` ディレクトリに保存する (既存の RTL, XDC, DCP は更新しない)。
